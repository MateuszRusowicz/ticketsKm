# Krzyżowa Music — ticketing

Ticket sales for a Polish music festival: ~10 general-admission concerts each
August, three languages (PL/EN/DE), two currencies (PLN/EUR), Stripe with local
payment methods. Next.js monolith on Vercel, Postgres on Neon.

**The back-office works. The storefront is a placeholder.** Payments, email, PDF
tickets and the door scanner are not built.

## How to work on this project

### Verify against the codebase, not against the plan

**This is the rule that matters most, and the one most often broken.**

Plans and design documents describe intent. The repository describes reality,
and they drift. Before writing a plan step or executing one, open the files it
touches and confirm its claims. A critique pass in August 2026 found five
blockers in a freshly written plan — a test setup that could not render
components, an ESLint rule banning an import the plan required, an uninstalled
dependency, schema fields on the wrong table, and seed data that could not
exercise the states the plan verified. Every one was visible in the repo and
none was visible in the design documents.

When writing a plan, read: `package.json`, `vitest.config.mts`,
`eslint.config.mjs`, `prisma/schema.prisma`, and the modules the plan will
touch. Confirm the dependencies it assumes are actually installed.

### Update the plan at the moment of discovery

When reality contradicts the plan, fix the plan **in the same turn**, not at the
end of the task. Append to the plan's **Findings log** and correct the affected
step. Batching these loses them, and a plan that is quietly wrong is worse than
no plan — someone will follow it.

This has happened well over a dozen times. The plans are only useful because
they stay true.

### Verify before claiming

Never report something passes without running it and showing the output. From a
**clean tree**, because a warm one hides the Next 16 generated-type failures
that only appear in CI:

```bash
rm -rf .next next-env.d.ts tsconfig.tsbuildinfo
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

Run the suite **twice** when a change adds tests asserting exact row counts —
test files share one database and run sequentially, so ordering bugs appear only
on the second run.

### Never commit

Only the repository owner commits. Stop at the boundary, say what changed, and
give the command.

### Secrets never enter a transcript

Not connection strings, not generated passwords. Both have leaked once. Redirect
script output to a git-ignored file **inside the repo** (`.env*` is ignored) —
never to `/tmp` or an agent scratchpad, which get cleared and have already
destroyed a set of production passwords.

## Traps

Rediscovering these costs an hour each time.

**Stack is newer than most guidance assumes** — Next 16, React 19, Prisma 7,
Tailwind 4, Vitest 4, Zod 4, Node 24. Check `plan/00-decisions.md` before
writing against a remembered API.

- **Prisma 7 needs a driver adapter.** `new PrismaClient()` with no options
  throws. Configured once in `src/lib/server/db.ts`.
- **Prisma client imports from `@/generated/prisma/client`**, not
  `@prisma/client`. Git-ignored build output, regenerated by `postinstall`.
- **`directUrl` was removed from the schema.** Migrations use `DIRECT_URL` via
  `prisma.config.ts`; the app uses pooled `DATABASE_URL` via `db.ts`.
- **`pnpm db:reset` is gated.** Prisma 7 refuses `migrate reset` without
  `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION`, even locally. The seed upserts,
  so `pnpm db:seed` usually makes the reset unnecessary.
- **`import 'server-only'` throws under Vitest and tsx.** Tests alias it. CLI
  scripts must not import from `src/lib/server/` at all — shared code goes in
  `src/lib/shared/`.
- **Components may not import `@/lib/server/*`.** `eslint.config.mjs` enforces
  it with no `allowTypeImports` escape; even `import type` fails. Shared types
  go in `src/lib/shared/`.
- **Tests are Node-environment with no DOM.** `vitest.config.mts` sets
  `environment: 'node'` and `include: ['tests/**/*.test.ts']` — no `.tsx`, no
  jsdom, no `@testing-library/react`. **Test pure functions, not components.**
- **`next typegen` must run before `tsc`.** Next 16 writes route types into
  git-ignored `.next/`, so typecheck passes locally and fails in CI otherwise.
- **`middleware.ts` is `proxy.ts` in Next 16.**
- **Route groups appear in import paths** (`@/app/(admin)/admin/...`) but not in
  URLs. `(shop)` and `(admin)` are two separate root layouts.
- **`next lint` was removed.** The lint script is plain `eslint`.
- **Money is integer minor units.** Never floats, never FX conversion — each
  concert carries an explicit PLN and EUR price.
- **Prices and counters are on `TicketType`; capacity is on `Event`.**
  Availability spans both: `event.capacity − tt.soldCount − tt.heldCount`.
- **Times are UTC; admins enter Warsaw local.** Checking in psql needs a double
  cast: `("startsAt" AT TIME ZONE 'UTC') AT TIME ZONE 'Europe/Warsaw'`. A single
  cast runs it backwards and makes correct data look broken.
- **`psql` and `pg_dump` do not work here.** The Debian `pg_wrapper` shim is on
  `PATH` so `command -v psql` succeeds, but no client package is installed.
  Query through Prisma instead. `pg_dump` has no substitute —
  `sudo apt install postgresql-client-16`.
- **Two numbering schemes in `plan/`.** Design docs (00–10) and executable plans
  (`steps/`) number differently: design `05` is Admin & scanner, executable `05`
  is Payments. `plan/README.md`'s table is authoritative for executable plans.

## Commands

```bash
pnpm dev                          # :3000
pnpm test                         # vitest against km_test
pnpm typecheck                    # next typegen && tsc --noEmit
pnpm lint
pnpm db:seed                      # upserts; safe to re-run
pnpm admin:create <email> <name> [ADMIN|SCANNER]
pnpm admin:reset-password <email>
docker compose up -d              # Postgres 16; km_dev + km_test
```

**Never run `pnpm db:seed` against production** — the seed password is published
in this repository.

## Branching

`main` is production and is what Vercel deploys. `development` integrates
finished features. Work happens on `feat/*` branches off `development`.

Until launch **every environment runs on the Neon `development` branch** with
dummy data; the real database is connected once at the end (Plan 02 Task 9).
