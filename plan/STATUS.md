## Things that will bite you if you forget them

Full detail in [`00-decisions.md`](00-decisions.md) under "Versions as built".
The short version:

- **Prisma 7 requires a driver adapter.** `new PrismaClient()` with no options
  throws. `PrismaPg` is configured once, in `src/lib/server/db.ts`.
- **The Prisma client imports from `@/generated/prisma/client`**, not
  `@prisma/client`. It is git-ignored build output regenerated by `postinstall`.
- **`import 'server-only'` throws under both Vitest and `tsx`.** Tests alias it
  to a stub; CLI scripts must not import from `src/lib/server/` at all. Anything
  shared between a script and the app goes in `src/lib/shared/`.
- **`next typegen` must run before `tsc`.** Next 16 generates global route types
  into `.next/`, which is git-ignored — so typecheck passes locally and fails in
  CI unless `typecheck` regenerates them.
- **Verify from a clean tree**: `rm -rf .next next-env.d.ts tsconfig.tsbuildinfo`
  before the gate. A warm tree hides exactly the failures CI will hit.
- **`psql` and `pg_dump` do not work here.** `command -v psql` succeeds because
  Debian's `pg_wrapper` shim is on `PATH`, but no client package is installed.
  Use the Prisma script in Task 6 Step 4 instead. `pg_dump` has no substitute
  and Task 8 needs it — `sudo apt install postgresql-client-16`.
- **Route groups appear in import paths** (`@/app/(admin)/admin/...`) even
  though they vanish from URLs.
- **`middleware.ts` is `proxy.ts` in Next 16.**
- **Checking stored times in psql needs a double cast:**
  `("startsAt" AT TIME ZONE 'UTC') AT TIME ZONE 'Europe/Warsaw'`. A single cast
  runs the conversion backwards and makes correct data look broken.

## Verification gate

Every task ends with this, from a clean tree:

```bash
rm -rf .next next-env.d.ts tsconfig.tsbuildinfo
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

Run the test suite **twice** when a task adds tests that assert exact row
counts — files share one database and run sequentially, so ordering matters.
